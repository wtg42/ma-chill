## MODIFIED Requirements

### Requirement: 四列式主桌面
主畫面 SHALL 改為三段式 shell 版面，而非四列式牌桌。由上至下依序為：頂部狀態列、中間事件流、底部命令輸入列。狀態列負責摘要局況與可用命令，中間區域負責顯示回合事件與系統回饋，底部則為玩家的主要輸入入口。

#### Scenario: shell 主畫面初始化
- **WHEN** 玩家進入對局主畫面
- **THEN** 畫面顯示頂部狀態列、中間事件流與底部命令列三個區塊

#### Scenario: 視窗高度有限時仍保留命令列
- **WHEN** terminal 高度不足以完整顯示所有內容
- **THEN** 系統優先保留頂部狀態列與底部命令列，中間事件流可裁切或捲動

## ADDED Requirements

### Requirement: 頂部狀態列顯示局況摘要
系統 SHALL 在主畫面頂部顯示局況摘要，至少包含當前局風／回合資訊、四家分數、輪到誰，以及目前可執行的遊戲命令摘要。

#### Scenario: 收到 turn_changed 後更新狀態列
- **WHEN** TUI 收到新的 `turn_changed` 訊息
- **THEN** 頂部狀態列同步更新目前行動玩家與可用命令摘要

### Requirement: 中間區域為可回溯事件流
系統 SHALL 以時間順序顯示遊戲事件流，內容包含摸牌、棄牌、吃碰槓胡、勝負結果、系統提示與命令執行回饋。最新內容 SHALL 出現在事件流尾端，使用者可回看較早訊息。

#### Scenario: 玩家打牌後寫入事件流
- **WHEN** 任意玩家完成棄牌
- **THEN** 中間區域新增一筆對應事件，描述是哪位玩家打出了哪張牌

#### Scenario: 命令解析失敗時寫入事件流
- **WHEN** 玩家輸入錯誤指令或當前不可執行的命令
- **THEN** 中間區域新增一筆清楚的錯誤或提示訊息

### Requirement: 底部命令列常駐可用
系統 SHALL 在主畫面底部顯示常駐命令列，提供目前輸入內容、placeholder 與最近一次命令結果；玩家不需切換到其他畫面即可輸入命令。

#### Scenario: 玩家準備輸入下一個命令
- **WHEN** 主畫面處於可互動狀態
- **THEN** 底部命令列保持可見，並可立即接受新的文字輸入

## REMOVED Requirements

### Requirement: AI 家列內容（最低揭露原則）
**Reason**: 主畫面不再以四列牌桌作為主要資訊承載形式，AI 的狀態改由頂部摘要與事件流表達。
**Migration**: 將 AI 手牌張數、副露與風位資訊轉移為 shell 狀態列摘要或事件流內容。

### Requirement: 玩家列內容
**Reason**: 玩家互動主入口改為底部命令列，不再依賴固定高度的玩家列與其中的熱鍵提示帶。
**Migration**: 將玩家可執行動作與局面資訊改由頂部狀態列與底部命令列提示。

### Requirement: 最新棄牌區（各列右側）
**Reason**: 最新棄牌不再以各列右側固定欄位呈現，而改用事件流依時間順序表達。
**Migration**: 將最新棄牌寫入事件流，必要時在狀態列補充最近事件摘要。

### Requirement: 棄牌區以 dialog 顯示
**Reason**: shell 版面改以事件流與命令查詢呈現歷史資訊，不再以固定 popup/dialog 作為主要互動方式。
**Migration**: 若仍需查看歷史，可由後續 slash 指令或 shell 子視圖提供。
